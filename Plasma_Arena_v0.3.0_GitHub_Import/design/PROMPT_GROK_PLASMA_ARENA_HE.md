# משימת פיתוח לגרוק — SpaceAces77 Plasma Arena v0.1

אתה סוכן הפיתוח של **Plasma Arena**, מיני־שלב ארקייד עצמאי ב־SpaceAces77.

**חשוב:** זו אינה `Plasma Sea` (מימד הים והדולפינים), שכבר הוקצתה ל־Claude. אל תשנה או תשכתב אותו. קרא תחילה את `START_HERE.md`, את `GDD_PLASMA_ARENA_v0.1_HE.md` ואת `MODULAR_CONTENT_CONTRACT.md`.

## המשימה
פתח בפועל Vertical Slice שחיק ב־**Phaser 3 + TypeScript**, במבט 2D עם שכבות 2.5D קוסמטיות אם מועיל. התבסס על קוד משחק קיים רק אם הוא זמין ונבדק בפועל; אחרת הקם אב־טיפוס עצמאי ואמור זאת ב־HANDOFF. אל תעמיד פנים שבוצע מחזור קוד שלא התרחש.

החוויה: שחקן נע בזירה, יורה בגושי פלזמה קופצים, מתחמק מהם, והגושים מתפצלים לגופים קטנים ומהירים יותר. המשחק צריך להיות מהנה, קריא, עם תגובות פגיעה מספקות וקושי שעולה בהדרגה. השתמש בפלייסהולדרים מקוריים; אל תחקה נכסים של משחק מסחרי.

## חובה באב־הטיפוס
1. רצף משחק מלא: Start → 3 Waves → Win/Lose → Retry.
2. שמאל/ימין, קפיצה, ירי, מעבר בין לפחות שני כלי נשק או מצבי נשק. בקרת מקשים מתועדת.
3. 3 סוגי סכנות פלזמה, כולל התפצלות מדורגת עם מגבלת כמות גופים.
4. 2 מכשולים או סכנות זירה, עם חיווי מקדים.
5. 2 תצורות זירה נטענות מקובצי נתונים (הן יכולות לשתף אותה גאומטריית בסיס).
6. שיפור קריאות: הצללות/משוב פגיעה, הגנות מפני פגיעות לא הוגנות, HUD נקי.
7. מצב ניסוי לאנרגיה משותפת אם יש זמן, ללא תלות של המשחק בו; לא ליצור מערכת מורכבת על חשבון מכניקת הליבה.

## דרישה ארכיטקטונית קשיחה
**New content = data change. New mechanic = isolated behavior module.**

- כל תוכן בר־הרחבה מוכנס ל־`data/` עם JSON תקף וסכמה מאומתת: אויבים/פלזמות, נשקים, קליעים, סכנות, גלים, זירות, נכסים וערכי איזון.
- בנה Factories/Registries של התנהגויות שמזהות מפתחות כגון `bounce`, `split`, `move_horizontal`, `projectile`, `area_slow`.
- קוד המשחק המרכזי לא יכלול `if (entityId === '...')` או מספרי spawn קשיחים עבור סוג תוכן מסוים.
- שליטה, פיזיקה, HUD, טריגרים, התפצלות, Damage/Hitboxes, Lifecycle ו־Asset Catalog צריכים להיות מופרדים למודולים.
- אין צורך ב־Framework אוניברסלי או ב־ECS מסובך; העדף מערכת פשוטה, ברורה ומורחבת.
- מצבי כשל לא ידועים (ID חסר, התנהגות לא מוכרת, ערך שלילי, מעגל התפצלות) חייבים להפיק שגיאה קריאה או fallback מוגדר, בלי קריסה שקטה.

## הוכחת מודולריות
בתיעוד ובבדיקות טכניות יש להדגים **ללא שינוי בקוד TypeScript**:
- יצירת סוג גוש פלזמה חדש מתוך התנהגות קיימת.
- שינוי שרשרת ההתפצלות של גוש.
- יצירת נשק חדש המשתמש בהתנהגות ירי קיימת.
- שינוי הרכב גלים.
- הוספת מכשול/סכנה קיימים לזירה ושינוי מקום הופעתם.
- טעינת זירה חלופית.

התנהגות חדשה באמת יכולה לדרוש מודול קוד חדש. אל תבטיח יכולות שלא מומשו.

## קונספט עלילתי ושילוב עתידי
Plasma Arena היא כרגע יחידה 8 בסדר קמפיין **מוצע בלבד**, לפני Asteroid Minefield, ואין לקבע את מיקומה או את סיפור התחנה כקאנון. אין לחבר בינתיים את הפרויקט למנוע הקמפיין. אם מתאים, הגדר `missionComplete`/`missionFailed` כ־event או API עתידי מבודד, בלי לשנות חוזים משותפים קיימים.

## בדיקות ומסירה
בעל הפרויקט יבצע את בדיקות המשחקיות והאיזון בעצמו. עליך לוודא באופן אמיתי `npm ci`/`npm install`, TypeScript/build, טעינת הנתונים, והרצה בסיסית בדפדפן אם הסביבה מאפשרת. דווח בדיוק מה עבר ומה לא יכולת לבדוק.

מסור **ZIP עצמאי** הכולל את המשחק והקבצים הדרושים להפעלה ללא אינטרנט, כל קוד המקור, `package.json`, נתוני JSON, בדיקות טכניות, `PLAY_HE.md`, `HOW_TO_ADD_CONTENT_HE.md`, `QA_TECHNICAL.md`, ו־`HANDOFF.md`.

העדף משחק שאפשר לפתוח ישירות כקובץ HTML מקומי. אם הגבלות הדפדפן מחייבות שרת מקומי, ספק כלי הפעלה מקומי פשוט ללא הורדת תלויות בזמן ההפעלה, ותעד זאת בבירור. **אין CDN או נכסים חיצוניים בזמן משחק.**

אל תשנה את מאגר SpaceAces-Phaser הראשי, אל תבצע Merge, אל תדרוס את Plasma Sea או שום מודול אחר. עבוד על אב־טיפוס עצמאי בלבד. בסיום ספק קובץ ZIP להורדה, לא רק תיאור או קטעי קוד.
